## **Weekly Scope Evaluation Protocol**

### **Step 1: Progress Assessment (15 minutes)**
**Roadmap Validation**
- Compare completed tasks against your ROADMAP.md milestones
- Calculate percentage completion for current phase (Phase 1: Days 1-7, etc.)
- Identify any tasks that took longer than estimated

**Quality Gate Check**
- Verify all completed features are **PLAYABLE** and **TESTABLE** per your development philosophy
- Confirm 60fps performance target maintained with current entity count
- Review Bug Tracker for any Quadrant 1 (critical) issues blocking progress

### **Step 2: Remaining Work Analysis (20 minutes)**
**Task Breakdown Evaluation**
- List all remaining tasks for current phase with honest time estimates
- Identify dependencies between tasks that could cause bottlenecks
- Calculate total remaining effort vs. available development days

**Risk Assessment**
- Flag any tasks that seem more complex than originally estimated
- Identify features that haven't been prototyped yet (higher risk)
- Note any external dependencies (AI art generation, Steam approval, etc.)

### **Step 3: Scope Decision Matrix (10 minutes)**
**Feature Categorization**
- **Core Features**: Essential for minimum viable product (combat, health, basic AI)
- **Enhancement Features**: Improve experience but not launch-critical (multiple weapon types, complex AI)
- **Polish Features**: Nice-to-have improvements (visual effects, audio polish)

**Backlog Decision Framework**
If behind schedule, apply this hierarchy:
1. **Preserve Core Features** - Never compromise basic gameplay loop
2. **Defer Enhancement Features** - Move to post-launch updates
3. **Eliminate Polish Features** - Focus on functionality over aesthetics

### **Step 4: Timeline Adjustment (15 minutes)**
**Schedule Recalibration**
- If on track: Continue with planned roadmap
- If 1-2 days behind: Identify specific features to simplify or defer
- If 3+ days behind: Trigger major scope reduction protocol

**Documentation Updates**
- Update ROADMAP.md with any deferred features
- Move backlogged items to "Post-Launch Content" section
- Adjust daily task estimates for remaining development time

## **Implementation Within Your Current System**

### **Integration with Progress Reports**
Add a **Weekly Scope Review** section to every 7th Progress Report covering:
- Phase completion percentage
- Features moved to backlog with justification
- Timeline adjustments made
- Risk mitigation strategies implemented

### **Backlog Management Strategy**
Create a **BACKLOG.md** document tracking:
- **Deferred Features**: Specific items moved from current development
- **Post-Launch Roadmap**: Features planned for updates after commercial release
- **Community Requests**: Ideas that emerge during development but don't fit launch scope

### **Decision Criteria for Scope Cuts**
When features must be cut, prioritize based on:
1. **Commercial Impact**: Does this feature affect Steam store appeal or reviews?
2. **Technical Risk**: How likely is this feature to introduce bugs or performance issues?
3. **Development Time**: Can this be implemented in post-launch updates more efficiently?
